## لماذا محلل خاص وليس xEdit وحده

## الجداول (SQLite: `03_translation/db/l10n.sqlite`)
| الجدول | المحتوى |
|---|---|
| `string_refs` | كل استخدام لرقم نص: form_key، نوع السجل، الحقل، EditorID، تفاصيل (المرحلة، رقم الهدف، رقم الرد) |
| `records` | كل سجل له EditorID أو اسم |
| `quests` | المراحل وسجلاتها، الأهداف ونصوصها، الـaliases بأرقامها وأسمائها |
| `topics` | DIAL: المهمة، النوع الفرعي (CUST/HELO/ATCK…)، الفرع |
| `infos` | INFO: الموضوع، السابق (PNAM)، المتكلم، خيار اللاعب، الردود بالترتيب، الشروط كاملة |
| `speakers` | NPC_: الاسم، الاسم المختصر، الجنس، العرق، نوع الصوت، الفصائل |
| `scenes` | SCEN: المهمة، وإجراءات الحوار (alias المتكلم، الموضوع، الترتيب) — 2,142 مشهداً |
| `actor_refs` | ACHR ← الشخصية الأساسية (13,075) لحل الـaliases ذات المرجع المفروض |

`source_strings` أصبحت تحمل لكل نص: `record_type`, `form_id`, `editor_id`, `field`, `category`, `quest_edid`, `speaker`, `context_flags`.

## قواعد الاستنتاج
- **المتكلم:** GetIsID أو ANAM ← شخصية؛ وإلا GetIsVoiceType ← `voice:`؛ وإلا GetInFaction ← `faction:`؛ وإلا GetIsRace ← `race:`؛ وإلا GetIsAliasRef ← `alias:<Quest>.<Alias>`. ثم إن بقي المتكلم مجهولاً أو فئة عامة فقط ← إجراء الحوار في المشهد الذي يستخدم الموضوع (SCEN → ALID). أي alias يُحلّ إلى شخصية عبر `ALUA` (ممثل فريد) أو `ALFR` (مرجع مفروض ← `ACHR.NAME`)، ويُحفظ اسم الـalias في `speaker_alias`. إذا أعطت المشاهد أكثر من مرشح مختلف يُسجّل `multiple:` (0 حالات حالياً).
- **المخاطبة بالجنس:** `player_gender_conditioned` = يوجد GetPCIsSex أو GetIsSex على غير المتكلم. العربية تحتاج «أنتَ/أنتِ»، ولا يمكن تبديل سطر غير مشروط وقت التشغيل ← صيغ محايدة حيث أمكن.
- **الأسطر المشتركة:** نص واحد لعدة متكلمين ← نبرة محايدة متوافقة مع كل المتكلمين.
- **النصوص المكررة:** مفتاح الذاكرة = `source_sha1 + record_type + field + speaker_class`.
