# خطة تعريب Skyrim Special Edition — تقرير المرحلة الأولى (فحص للقراءة فقط)

## السياق
المطلوب تعريب احترافي كامل للعبة مع منع الأخطاء المتكررة (الإملاء، الحرفية، أسماء غير موحدة، حوار غير طبيعي) عبر بحث ومسرد وفحص آلي ومراجعة مستقلة **قبل** قبول أي دفعة. هذا التقرير مبني على فحص فعلي للملفات (لم يُعدَّل أي ملف، ولم تُشغَّل اللعبة، ولم يُثبَّت أي برنامج). ما لم أتحقق منه بنفسي موسوم بـ «غير مُتحقَّق».

## 3) كيف يُستخرج كل نص مؤهل

1. **لقطة أساس:** SHA-256 لكل ملف في `Data` والجذر ← `00_baseline/hashes.json`. لا يُكتب شيء داخل مجلد اللعبة أبداً.
2. **استخراج الأرشيفات المطلوبة فقط** (strings، interface، scripts) إلى `02_extracted/1.7.104/` (خارج OneDrive أو مستثنى من المزامنة).
3. **محلل STRINGS** (`tools/strings_io.py`): قراءة/كتابة الصيغ الثلاث، اختبار **roundtrip byte-identical** على الـ30 ملفاً الإنجليزية قبل أي استخدام.
4. **الجرد:** كل نص ← صف في `translation_inventory` بمفتاح ثابت `plugin|file_kind|string_id`.
5. **ربط السجل:** سكربت xEdit يصدّر لكل String ID: نوع السجل، FormID، EditorID، الحقل (FULL/DESC/NAM1/RNAM/CNAM/ITXT...) ← يحدد الفئة (حوار، خيار لاعب، اسم عنصر، وصف، هدف مهمة، كتاب...).
6. **الواجهة:** `translate_english.txt` (مفاتيح `$`) + فحص نصوص ثابتة داخل SWF عبر FFDec.
7. **Papyrus:** مسح جدول النصوص في `.pex` وتصنيف ما يظهر للاعب (Notification/MessageBox) مقابل المعرّفات الداخلية — الثاني لا يُلمس.
8. **التصنيف:** `PLAYER_VISIBLE` / `TECHNICAL` / `DO_NOT_TRANSLATE` (معرفات، أسماء ملفات، نصوص اختبار) / `BLOCKED_CONTEXT`.

## 4) كيف يُعاد بناء السياق السردي

- **قاعدة سياق** (SQLite: `quest_context_database`): QUST (المراحل، الأهداف، الـaliases) ← DIAL (المواضيع) ← INFO (السطور، ترتيبها، `PNAM` السابق، الردود) ← CTDA (الشروط: `GetIsID` للمتكلم، `GetStage`، الجنس `GetIsSex`، العرق، الفصيل).
- **المتكلم والمخاطَب:** من شروط `GetIsID`/`GetInFaction`/VoiceType، والمخاطَب = اللاعب افتراضياً، مع علم `gender_sensitive` إذا وُجد شرط جنس أو الجملة تخاطب اللاعب مباشرة.
- **سلسلة الحوار:** كل سطر يُترجم ومعه السطر السابق واللاحق وخيارات اللاعب ونص المرحلة.
- **النصوص المكررة بمعانٍ مختلفة** (مثل "Yes."، "What?"، "Take it."): مفتاح الذاكرة = النص + فئة السياق + المتكلم، لا النص وحده.
- **LORE_DATABASE:** من بيانات اللعبة أولاً (الكتب، journals، أوصاف) ثم UESP كمرجع ثانوي؛ كل معلومة بحقل `source` و`confidence: confirmed|inferred` — بلا اختراع.
- ما لا يُحسم سياقه ← `BLOCKED_CONTEXT` ولا يُترجم حتى يُحقق فيه.

## 5) كيف تتحقق جودة عربية ممتازة من أول مرة

- **قبل أي ترجمة جماعية:** المسرد المركزي (شخصيات، أماكن، ممالك، أعراق، فصائل، صرخات ولغة التنانين، أسلحة، مواد، تعاويذ، مزايا، كتب، مهام) بحقول: العربي المعتمد، المعنى، المبرر، الصيغ الممنوعة، المصدر، حالة الاعتماد.
- **سياسة المصطلحات:**
  - الأسماء العلم (Ulfric, Whiterun, Alduin) ← نقل صوتي موحد بقواعد مكتوبة (ف/ڤ، ث، الألف الممدودة، أل التعريف).
  - الأسماء ذات المعنى (Whiterun = «وايترن» أم «الجري الأبيض»؟) ← قرار موثّق لكل فئة، لا لكل سطر.
  - لغة التنانين (Fus Ro Dah) ← تُكتب بالحروف العربية كلفظ مع حفظ المعنى في الشرح، لا تُترجم داخل الصرخة.
  - المصطلحات العامة (Perk، Skill، Enchanting) ← ترجمة عربية لا نقل صوتي.
- **دليل الأسلوب** (`07_ARABIC_STYLE_GUIDE.md`): فصحى معاصرة سلسة، ترقيم عربي (، ؛ ؟)، همزات صحيحة، بلا تشكيل إلا لرفع لبس، أرقام موحدة، تعليمات مهام بصيغة أمر واضحة.
- **دليل أصوات الشخصيات:** ملك/جندي/عالم/كاهن/تاجر/تنين/لص/مدني خائف، مع مستوى الرسمية والمفردات المميزة.
- **الترجمة بالسياق:** كل دفعة تحمل المسرد المطابق فقط + سياق المهمة + المتكلم (استرجاع انتقائي، لا إرسال قاعدة المعرفة كاملة).
- **مراجعات مستقلة:** مُترجِم ← مُراجِع دلالي (يقارن بالإنجليزي) ← مدقق لغوي ← مراجع أسلوب وحوار ← فاحص مسرد ← فاحص تقني. كل مرحلة جلسة/نموذج مستقل بتعليمات مختلفة، لا يُطلب من المترجم تقييم نفسه.
- **ذاكرة ترجمة** لا تعيد استخدام إلا المعتمد، وتفرّق السياقات.

## 6) كيف تُكتشف الأخطاء آلياً

`qa/run_qa.py` على كل دفعة، ونتيجته في `qa_results`:

| الشدة | أمثلة الفحوص |
|---|---|
| CRITICAL | وسم/Alias/Global محذوف أو معدّل، String ID مفقود أو مكرر، ترميز غير UTF-8، تجاوز طول يكسر الواجهة، `<p>`/`<font>` غير متوازن، حرف خارج تغطية الخط |
| HIGH | نفي مفقود (not/never ↔ لا/لم/لن/ليس)، أرقام أو كميات مختلفة، مصطلح مخالف للمسرد، اسم شخصية غير معتمد، إنجليزي غير مترجم، عدم تطابق الجنس مع شرط CTDA، خطأ إملائي من Hunspell |
| MEDIUM | همزات (ان/إن/أن، اذا)، ى/ي، ة/ه، تكرار ركيك، طول > 130%، نقل صوتي لمصطلح عام، ترقيم لاتيني |
| LOW | تحسينات أسلوبية مقترحة |

- لا تُقبل دفعة فيها CRITICAL أو HIGH مفتوح.
- فحص دلالي إضافي بنموذج مستقل (back-translation مقارنة) لعينة من كل دفعة + كل النصوص الحساسة (خيارات اللاعب، أهداف المهام).
- **نقاط مراجعة بشرية** (أنت): المسرد، الطيار، وعينة عشوائية 2% من كل دفعة كبيرة.

## 7) كيف يُعالج العرض العربي RTL

**الحقيقة التقنية:** Scaleform في Skyrim لا يشكّل العربية، ولا يقلب الاتجاه، ويلف الأسطر من اليسار. الحل المعروف (نص مقلوب مسبقاً) يكسر الأسطر الطويلة لأن المحرك يلف بعد القلب — وهذه مشكلة المشاريع الحالية.

**القرار: مساران، نثبت أحدهما بالتجربة قبل الإنتاج.**

**المسار A — بدون DLL (الافتراضي، مضمون التوافق):**
1. خط عربي مرخص (مثل Noto Naskh/Amiri/Cairo حسب الاختبار) يُضاف له presentation forms (U+FB50–FDFF، U+FE70–FEFF) ← يُبنى `interface/fonts_ar.swf` بـFFDec بنفس أسماء الخطوط المتوقعة.
2. `fontconfig.txt` معدّل يربط `$EverywhereFont`/`$DialogueFont`/`$SkyrimBooks`/`$HandwrittenFont` بالخط العربي، ويضيف الحروف العربية إلى `validNameChars`.
3. **التشكيل والقلب وقت البناء فقط:** الجدول يبقى عربياً منطقياً، والبناء يشكّل ← يطبق bidi (أرقام وإنجليزي ووسوم بالترتيب الصحيح) ← **يلف السطر بنفسه** بقياس عرض الحروف الفعلي من الخط وبعرض حقل كل سياق (ترجمة الحوار، قائمة الحوار، دفتر المهام، الكتب، وصف العنصر، الرسائل) ← يقلب كل سطر على حدة ← يُدخل فواصل أسطر صريحة بحيث لا يحتاج المحرك للالتفاف.
4. جدول `ui_contexts.json` لعرض/مقاس كل حقل يُقاس من SWF ويُصحح بلقطات من اللعبة.

**المسار B — بحث تقني (Spike) بإضافة SKSE جديدة:** تطبيق تشكيل + bidi + لف وقت العرض داخل Scaleform (Translator/OnBidirectionalText أو hook على تخطيط TextField) فيبقى النص منطقياً ويلف بشكل صحيح بأي دقة شاشة. لا يعدّل EXE أو DLL موجوداً، لكنه يتطلب تثبيت SKSE ويجعل التعريب يعتمد على إصدار اللعبة. يُقيَّم فقط إذا فشل المسار A في الكتب والحقول متغيرة العرض.

**إثبات المفهوم قبل أي شيء:** 14 سطراً اختبارياً (قصير، طويل، مختلط عربي/إنجليزي، أرقام، Alias، ترقيم، لام-ألف، كتاب متعدد الصفحات، ترجمة حوار طويلة، خيار حوار، اسم عنصر، وصف تعويذة بـ`<mag>`) ← لقطات داخل اللعبة ← قرار مكتوب.

## 10) ترتيب التنفيذ الدقيق

1. **التأسيس:** هيكل المشروع، `hashes.json`، ملفات `docs/01–15` (هيكل أولي)، Git محلي بدون push.
2. **الأدوات (بإذنك):** تثبيت والتحقق من الإصدارات.
3. **الاستخراج:** `strings_io.py` + roundtrip byte-identical لكل الملفات الـ30 ← `translation_inventory` (92,360 صفاً).
4. **ربط السجلات بالسياق:** تصدير xEdit ← `quest_context_database` + تصنيف الفئات وBLOCKED_CONTEXT.
5. **إثبات العرض (أهم بوابة تقنية):** خط + fontconfig + 14 سطراً ← لقطات ← قرار A أو B موثّق.
6. **البحث القصصي:** LORE_DATABASE ثم المهام الرئيسية والـDLC، وملفات الشخصيات الرئيسية.
7. **المسرد المركزي:** نحو 3,000–5,000 مصطلح (أسماء FULL للسجلات أولاً)، تعتمده أنت.
8. **دليل الأسلوب + دليل الأصوات + قواعد QA.**
9. **الطيار:** 12 فئة المطلوبة (المهمة الرئيسية، حوار متفرع، قتال، تنين، كتاب، رسالة، هدف مهمة، عنصر، تعويذة، قائمة، حوار حساس للجنس، حوار معرفي) ← خط المراجعة كاملاً ← تحديث القواعد ← تكرار حتى صفر CRITICAL/HIGH ← لقطات داخل اللعبة.
10. **الإنتاج على دفعات** بالترتيب: الواجهة والقوائم ← أسماء العناصر والتعاويذ والمزايا ← أهداف المهام ← الحوار الرئيسي ← الفصائل ← الـDLC ← المهام الجانبية ← الحوار العام ← الكتب ← CC.
11. **التغطية والتكامل:** تقارير لكل ملحق ومهمة وفئة؛ لا ادعاء 100% دون جرد.
12. **التغليف والاختبار:** بناء من الصفر، تحقق العدد والـIDs، اختبار داخل اللعبة بقائمة لقطات، إصدار قابل للإزالة.

## المخاطر والعوائق المعروفة
- **الالتفاف العربي في Scaleform** هو الخطر الأول؛ لا إنتاج جماعي قبل حسمه بالتجربة.
- الإصدار 1.7.104 أحدث من أغلب أدوات المجتمع؛ توافق xEdit/xTranslator مع 1.7 **غير مُتحقَّق** (ملفات STRINGS نفسها لم تتغير صيغتها حسب الفحص).
- 1.25 مليون كلمة: الجودة تتطلب وقتاً طويلاً؛ سأقيس الإنتاجية الفعلية بعد الطيار بدل الوعد بموعد.
- لا يمكن إثبات الجودة الأدبية آلياً بالكامل؛ مراجعتك للمسرد والعينات جزء أساسي.
- مشاريع التعريب الموجودة مرجع للمقارنة فقط؛ لا نستخدم أصولها دون إذن ترخيص صريح.

## التحقق
- roundtrip: إعادة بناء STRINGS بدون تغيير ← SHA-256 مطابق للأصل.
- بعد البناء: نفس عدد الـIDs لكل ملف، صفر وسوم مكسورة، فتح الملفات في xTranslator بدون أخطاء.
- محاكاة العرض (`simulate_render.py`) ثم لقطات داخل اللعبة لكل سياق — وما لم يُختبر داخل اللعبة لا يُوصف بأنه «مُتحقَّق».
- `hashes.json` قبل وبعد: مجلد اللعبة لم يتغير.
