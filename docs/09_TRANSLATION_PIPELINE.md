# 09 — خط الترجمة

## الدفعة
`03_translation/batches/<batch_id>/` = `input.json` (السطور + حزمة السياق لكل سطر) ← `draft.json` ← `review_*.json` ← `accepted.json`. كل ملف يحمل `source_sha1` لكل سطر.

## الخطوات (آلية، بلا انتظار طلب منك)
| الخطوة | المنفّذ | المخرج |
|---|---|---|
| A استرجاع السياق | أداة | حزمة السياق + المصطلحات المطابقة فقط |
| B الترجمة | مترجم (نموذج) | مسودة |
| C التكافؤ الدلالي | مراجع مستقل | ملاحظات معنى/نفي/أرقام/حذف |
| D الإملاء والنحو | Hunspell + مدقق مستقل | أخطاء |
| E الأسلوب والحوار | مراجع مستقل بدليل الأصوات | ملاحظات نبرة/طبيعية |
| F المسرد والاتساق | أداة | مخالفات |
| G التقنية | أداة | وسوم، ترميز، طول، تغطية الخط |
| H القبول | بوابة | صفر CRITICAL/HIGH |

المراجعون لا يرون تبرير المترجم، والمترجم لا يقيّم نفسه. كل إصلاح يعود عبر C–G من جديد.

## ذاكرة الترجمة
- تعيد استخدام `ACCEPTED` فقط، وبمطابقة سياق (`source_sha1 + record_type + field + speaker_class`).
- المطابقة التقريبية تُعرض كاقتراح ولا تُقبل آلياً.

## الاستئناف
الحالة في SQLite؛ أي دفعة تُستأنف من آخر خطوة مكتملة. تغيير `source_sha1` بعد تحديث اللعبة يعيد السطر إلى `DRAFT`.

## الكفاءة
حجم الدفعة حسب الفئة (مثلاً 40–80 سطراً حوارياً من نفس المهمة، أو كتاب واحد)، وسياق مسترجع انتقائياً.
